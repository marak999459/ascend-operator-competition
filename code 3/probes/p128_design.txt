P128 预登记 —— 给"抬 `nb`"加一道 incumbent 单元数护栏（纯 host，三行）

## 0. 一句话
`code/op_host/sparse_flash_attention.cpp:304` 那条迟滞从
```cpp
if (bestCost == 0 || cost * 20ULL < bestCost * 19ULL) {          // 现状 auto
```
改成"只有当**当前 incumbent 的单元数已经小于一档门槛**时才允许降档"：
```cpp
if (bestCost == 0 || (bestUnits >= P128_FLOOR ? false : cost * 20ULL < bestCost * 19ULL)) {
```
配 `uint64_t bestUnits = 0;`（L240 旁）与 `bestUnits = units;`（替换块内）。`P128_FLOOR = 2*coreNum = 80`。
kernel / tiling.h / tiling_key 三枚**逐字节不动**。

## 1. 为什么是这一刀（P127 的读数，不是理论）
P127 = 无护栏版（`bestCost == 0` 之外一律不替换 ⇒ 首位可行者直接胜出 = 最大 `nb` = 单元数下界）。
同一份字节两遍（`p127_submit.txt` / `p127_submit2.txt`，Pass 6/6、`precision_ratio` 全 1）：

| | C1 | C2 | C3 | C4 | C5 | C6 | Σ |
|---|---|---|---|---|---|---|---|
| 遍 A | 13.36 | 7.60 | 9.62 | 12.88 | 9.82 | 15.38 | **68.66** |
| 遍 B | 13.12 | 7.94 | 8.70 | 12.88 | 9.42 | 14.86 | **66.92** |
| 两遍均值 vs 22.33 那一遍 | **+75.6 %** | −6.8 % | **−12.9 %** | +7.5 % | **−10.9 %** | −1.3 % | **+2.7 %** |

⇒ 三条结论，第二条是本轮的靶：
1. **单点读数要两遍才算数**：C1 两遍 13.36/13.12（pristine 池 20 遍里 C1 最高观测 8.56 ⇒ 13.2 远在带外，不是抽卡）；C3 两遍 9.62/8.70 也低于池内 C3 最低观测 10.52。
2. **`nb↑` 不是"整轴无收益"，也不是"整轴有收益"**：四点里三点真受益（−7~−13 %），被一个点 +76 % 吃掉 ⇒ P126 那条"单元数每翻倍 ≈+20~25 %"是**单向**的（往下钉 = 纯亏成立；往上抬 = **有护栏才成立**）。
3. **C1 的机制**：pin 把它的单元数从 82 砍到 **41**（= `rows=41 ∧ qN≤8` 那一格），单元少了一半、`n_blk` 从 48 被 UB 挤到 40/32。在半分省不出墙的形状上，`n_blk` 那笔是净支出 ⇒ **受益的条件不是"能抬"，而是"抬了以后单元数仍然多"**（多到波数 ≥2 档，砍一半才落在墙上）。

⇒ 护栏就照这个机制写：**大档自己就没什么单元（< 80 = 2 波）⇒ 别拦模型降档（= 今天的 auto）；大档单元数 ≥ 80 ⇒ 保住大档**。门槛用 incumbent 的运行时算量，⛔ 不查形状表、⛔ 不认具体 case。

## 2. 镜像三臂（`probes/p128_model.py`，逐函数抄 host，只改判定那一行）
本地九例（对表 `p127_gaterun.txt` 的 pick 行）：

| | auto | pin(P127) | guard80 |
|---|---|---|---|
| p1 | nb2 k48 ks5 u8 | nb4 u4 | **=auto** |
| p2/p4/p6/w3/r64c65 | — | 与 auto 同档 | =auto（可证惰性） |
| big1 | nb4 k48 u256 | nb8 k40 u128 | **=pin**（本地已知 +6.6 %） |
| pn16a | nb8 k40 ks5 u8 | nb16 k32 ks10 u4 | =auto |
| pn32a | nb8 k40 ks1 u32 | nb16 k32 ks2 u16 | =auto |

⇒ **P128 在本地九例里只有 big1 一例响应**（8 例逐位等于 auto）⇒ 本地闸门只能验"没坏"，收益判定 100 % 在平台。这条要写进发次预期，别拿本地时间当信号。

平台族（`sbs=1 ∧ fp16 ∧ rows≥41`，扫 `qN∈{2,4,8,16,32}×rows∈{41…256}`，S2=8192）：
- `qN=2`：**全 auto**（pin≡auto，单元数已经在下界）⇒ 控制点。
- `qN=4`：`rows=41/48` 的 pin 单元数是 41/48 ⇒ **护栏把它们交回 auto** ⇒ 这一族正是 C1 的形状（82→41），预期被排除 ✅。
- `qN=8`：`rows≤64` 交回 auto，`rows≥96` 交 pin。
- `qN=16/32`：绝大多数格交 pin（`rows=41..64` 三格是**第三态**）。
- **第三态 = 既非 pin 也非 auto**：`qN=16 rows=41/48/64`（停在中途档，如 nb=8）与 FLOOR=64/128 时的少量格。族内计数：FLOOR=40 → 42 格 pin / 28 格 auto / **0 第三态**；64 → 30/36/4；**80 → 28/36/6**；128 → 20/46/4。
  ⇒ 取 80 的代价是 6 格落到"中间态"（响应方向未测），取 40 更干净但会把 C1 那类 41 单元的格重新交给 pin（41 ≥ 40 ⇒ 又踩同一个坑，只差 1 个单元）⇒ **不取 40**。80 与 41 之间留了近一倍余量，这是选 80 而不是 64 的理由（64 那一档 41→64 只有 1.5×）。

## 3. 预登记判据（Σ；噪声：pristine 池 20 遍均值 66.02、全距 5.52 %、Σ 带 ±2 %）
- **Σ ≤ −4 %（更快）** ⇒ 护栏成立 ⇒ **这就是新的最好字节**，留在榜上并把它当"选档"族里第一个正向落地；下一步 P129 = 扫 `FLOOR∈{40,160}` 看是不是单调（同一根轴，一发就能判）。
- **−4 % < Σ < +2 %** ⇒ 收益被第三态/残余负响应抵消 ⇒ 轴**没读出来**，但"单元数 ≥80 才受益"这条机制未被否证；回 auto，转 **P125（每单元 I/O 定价）**，不再在 `nb` 轴上花钱。
- **Σ ≥ +2 %** ⇒ 护栏没用（C1 那类损失不止一处，或者受益点在 `units<80` 那侧）⇒ **`nb` 轴在平台上结案**（三发：P126 钉低 +38 %、P127 无护栏 +2.7 %、P128 带护栏 ≥+2 %），§5 开一条"选档族的收益在平台上不可分离"的否定项，回到 P125。
- ⚠️ 逐点判读要**两遍**（本轮立的规矩）：若 Σ 落在"≤−4 %"分支，必须**立刻再发同一份字节一遍**，用两遍均值确认 C1 回带内、负响应点仍为负。

## 4. 闸门与发次链（照抄 P127 那一套，runner = `p128_pin.py` + `p128_{gate,precheck,submit,reissue}.sh`）
① `p128_pin.py check` + `npu.sh sync` → ② **命中数门**（远端 sed 之前）：`P128=1`、`FLOOR` 定义 1、`bestUnits` 3 处（声明/赋值/条件）、旧锚点 `cost * 20ULL < bestCost * 19ULL` 命中 1（还在，只是被护栏包起来）⇒ 加上 kernel 三枚 sha 不变 → ③ SoC sed（只在远端）+ build → ④ 探活 ×6 → ⑤ **时间指纹**：预期只有 `big1` 相对 pristine 变（+6~7 % ⇒ 落到 P127 的 nb=8 指纹上），其余八例逐位对表 pristine（p1 0.1192 / w3 5.32~5.44 / r64c65 18.83）⇒ **这就是"护栏在本地不是空操作、也不是全局空操作"的证据** → ⑥ `p32_gate.sh` 全量数值门（13 golden × 双 dtype + 13 expect + pn16a/pn32a）⇒ **超差必须 0**（`nb=16 / n_blk=32` 路径已在 P127 闸门里跑通过，这里复验）→ ⑦ §7.5：最后一次 sync（之后不再 build）→ 四枚 sha + `SOCEDEX=0` + 禁用词 0 → dry-run → submit → 读六点 → 按分支回发。
⛔ 提交字节里不许出现 `printf/cerr/TODO/调试`；⛔ 不许从 `code 3/submit/` 发；⛔ 429 退避 ≥8 min（P127 收尾实测 12 min 仍 429 ⇒ 窗口比旧记的更长）。
