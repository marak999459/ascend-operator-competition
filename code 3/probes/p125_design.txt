P125 预登记 —— 给"每单元付一次的那一段"定价（prologue / epilogue 双臂）
=====================================================================

立论来源（不改）：`#15.103` P123+P124 两把尺子合解 ⇒ **平台每 chunk 平均只填 ≈6.6 个 token**
⇒ 全部"每 chunk 固定税"的读数要**改读成"每单元"** ⇒ 那 ≈70 % 无价的落点是
**每单元一次的 I/O + 单元数本身**。单元数那半边已有单价（P126/P127，两侧不对称）；
这一发问的是**另外那半边**：一个单元"开工前 + 收工后"这两段到底值多少墙。

⚠️ 这是**计量器**不是杠杆：读到的数本身不涨分，它的价值在于"如果 prologue+epilogue 值
X %，那少付一次的写法（合并单元 / 让 prologue 跨单元复用）值多少"。**判据在下面第 5 条**。

1. 靶子（`op_kernel/sparse_flash_attention.cpp`，一个单元 = 一个 (head-block, shard)）
   - **prologue**：L456 `LoadQ(...)` + L459-461 三条 `Duplicate`（o 清零、m=MIN、l=0）。
     `LoadQ` 体内 = 每 `stageMax_` 头一组：两条 `CopyGm2Ub`（content / rope）+ 一对
     `MTE2_V` 旗标 + 逐头两条 `WidenToF32` + 一对 `V_MTE2` 旗标。
   - **epilogue**：L555 `WriteOut(...)` 的**尾巴**（`SetFlag/WaitFlag(V_MTE3=1)` +
     `CopyUb2Gm` + `MTE3_V=1`，以及 `lseOn_` 那一对 `DataCopyPad` + `V_MTE3/MTE3_V=2`）。

2. 幂等性（这是这一发能不能成立的全部理由，逐条查过）
   - **prologue 整体幂等**：`LoadQ` 是"GM→UB→(Cast)→UB"的纯函数，源地址（`qGm_+s1Base+…`、
     `qrGm_+ropeBase+…`）与目的（`kb`/`kr`/`q[i0+t*qRow]`）在重复调用之间都不变，且此时
     `kb`/`kr` 还没被 KV chunk 覆盖（覆盖发生在后面的 while 循环里）⇒ 重跑 N 遍写下的字节
     与跑一遍**完全相同**。`Duplicate(o/ml/ml[halfOff_])` 同理（常量写、不读回）。
     ⇒ 这一臂**不需要**P121 那套"只重读地址 + 不可达 sink"的构造。
   - 🔴 **`WriteOut` 整体不幂等**：它对 `o` 做**原位** `Muls(oi, oi, 1.0f/l)` ⇒ 跑两遍等于除
     `l²`。⇒ epilogue 一臂**只重复 DMA 尾巴**（从 `st` 读、往 `outGm_`/`maxGm_`/`sumGm_` 写，
     重复写同一批字节），`Muls`/`PackFromF32`/`GetValue` 那几行**一遍都不多跑**。
     这两行不改 `st`、不改 `o`，所以重复段是自足的：旗标 id 1/2 的 Set/Wait 成对出现在重复体内。
   - 两臂各自的"数值不变"是**可证**的，但照旧要过本地逐位门（下面第 4 条），不靠证明放行。

3. 臂定义（同一份 kernel 基线，各自 ×N；N 由本地标定挑，见第 4 条）
   - `q`：把 L456-461（`LoadQ` + 三条 `Duplicate`）包进 `for (uint32_t p125r = 0u; p125r < N; ++p125r)`。
   - `w`：把 `WriteOut` 内两段"旗标 + `CopyUb2Gm`/`DataCopyPad`"**各**包进同样的循环（⇒ `w` 的
     `p125r` 命中数 = 2，`q` = 1，这是两侧的区分门）。
   - 生成器 = `p125_pin.py N ARM OUT [PRISTINE]`：从 pristine 现生成、N 是**编译期字面量**（`<N>u`），
     不读环境变量；打补丁后自带断言（旗标 36 / `InitBuffer` 13 / `Muls(` 条数不变 /
     `Muls(oi, oi, 1.0f / l, rowC)` 仍恰好 1 条 ⇒ 原位归一**没被**重复）。
   - ⛔ 提交字节里不许留 `printf`/`TODO`/`#if 0`；发货前 `grep -c` 命中数当门。
   - 🔴 **构造性下偏（读的时候必须扣）**：重复段第二次起读的是**同一批 GM 行 / 写的是同一批地址**
     ⇒ 后 N−1 圈走的是热的，所以 `u(N)` 是**热价**，对"冷 I/O"系统性偏低（P119 的死端同一毛病）。
     ⇒ 这一发给的是"这一段**至少**值多少"，不是"至多"。

4. 本地标定（必经，P121 立的规矩：被折叠的重复段读出来永远是 0）
   - ⚠️ **口径订正（发第一批平台读数之前改的，不是读完以后）**：原写"若 N=1 与 N=2 时间差
     <0.3 % ⇒ 判被吸收 ⇒ 作废"。这一条在本发**结构上必然失败** —— 这里 `N=1` 就是"一遍都不多跑"
     （循环体跑一遍 = pristine 的工作量），所以 Δ(1)≈0 是**构造如此**，不是折叠的证据。⇒ 门重列：
     · **门 A（噪声底）**：`N=1` 的真实身份是**对照组**（字节变了、工作量没变）⇒ 逐例 |Δ(1)| 的最大值
       就是本场的 σ；σ > 1.5 % ⇒ 本场低档位读数一律不作依据。
     · **门 B（防折叠）**：每圈单价 `u(N) = 逐例中位 Δ(N)/(N−1)` 在**最大 N 跨度**上 `u_max/u_min ≤ 4`
       ⇒ 认线性、Δ 才可折回"一圈的价"；折叠/吸收的表现就是 u(N) 随 N 塌向 0。
       （为什么用逐例中位而不是最差档：最差档在低 N 上被噪声主导 —— 实测 p1 一例的 σ 就有 1.1 %，
       拿它算 u(2) 会让门 B 变成"比谁的噪声大"；最差档只留给门 C 当安全上限。）
     · **门 C（选档）**：取"七例里最差那例 Δ ≤ +15 %"的最大 N（P119/P121/P123 同一约定）。
     读数器 = `p125_read.py`（三条门算成结论，不靠人眼看大表）。
   - 阶梯：低场 N ∈ {1, 2, 8}、高场 N ∈ {16, 32, 64}（同机同次构建，七例 p1 p2 p4 p6 big1 w3 r64c65）。
     分两场是因为单场时间：Δ 只在**同一场的 N=0 基准**下比较，跨场不折算。
   - 数值门：`p32_gate.sh` 26 例双 dtype **超差全 0** + 逐位与 pristine 同（`SFA_F32=1` 那份也是）。
   - 参考单价：状态板 §4 那四条（碎拷贝 ≈50 ns/条、Fixpipe ≈0.7 µs/条、标量 GM 读 38.6 ns、旗标对
     ≈0.42 µs/轮，`LOG#15.70`）**是 AIC 侧的读数**，不能直接乘到这一段上 —— `LoadQ`/`WriteOut`
     跑在 MIX 1:2 的**向量核**上，而 AIV 侧条数单价实测 **8~12.3 ns/条**（P115）。
     ⇒ 这一段的先验**只能给到"每单元几 µs 以内"**，跨不到墙钟占比；占比本来就是这一发要问的东西。
   - ⇒ **N 由本地标定挑，不由先验挑**：取"本地 Δ ≤ +15 %"里最大的那一档（约定同 P119 ×2 /
     P121 ×7 / P123 ×63 —— 让重复段留在次要效应之前），并把这个 N 写回本文件再发货。
   - ✅ **标定已读完（两场共 14 档 × 七例，读数器 `p125_read.py`）⇒ 发货档已定：`q N=32`、`w N=16`**。
     · 门 A（对照 σ = 逐例 |Δ(N=1)| 最大）：q 1.10 % / w 0.15 % ⇒ 本地尺子够用。
     · 门 B（**最敏感例**的每圈单价 u(N) = Δ/(N−1)，N ∈ {16,32,64}）：
       q：p2 = 0.178 / 0.267 / 0.290 pp/圈（big1 0.234/0.260/0.279、p1 0.174/0.293/0.277 同形）⇒ 比 1.63；
       w：big1 = 0.738 / 0.807 / 0.797 ⇒ 比 1.09 ⇒ **两臂都认线性 ⇒ 重复段没被折叠，尺子在**。
       ⚠️ 低场 {1,2,8} 判不出：q 那一场的 Δ(8) 与它自己的 σ 同级（p1 上 1.26 vs σ 1.10），门 B 在高场
       Δ(64) ≈ 16×σ 上才算数 —— 这不算口径漂移，低场本来就是"先探有无"的，它的 u 虚高正是噪声。
     · 门 C（本地最差档 Δ ≤ +15 %）：q = +3.52(N16) / **+9.08(N32)** / +18.29(N64) ⇒ 取 32；
       w = **+11.08(N16)** / +25.01 / +50.20 ⇒ 取 16。
     · 顺带读到的**本地**单价（这一场的副产品，不是平台占比）：prologue 一圈 ≈ 0.24~0.29 % 墙、
       epilogue 一圈 ≈ 0.74~0.81 % 墙（都取最敏感例 big1）⇒ 在"填得满"的形状上 **epilogue ≈ 3× prologue**；
       `r64c65`/`w3` 两臂几乎不敏感（|u| ≤ 0.06，且 q 那列是常数偏移 = 噪声）。
       ⚠️ 平台每 chunk 只填 ≈6.6 token ⇒ 每单元固定税在平台上的**权重**应当大一个量级，这正是这一发要问的。

5. 判据（预登记，读的时候不许改口径）
   - **发法 = 每臂先一发高档**（N 由门 C 挑，本地最差档 Δ ≤ +15 %），拿它与 22 遍同字节池的
     Σ 基准（65.98，带 ±2 %）比：
     · Σ Δ 落进 ±2 % 带 ⇒ 该臂单价 ≤ 2/(N−1) % ⇒ **一发关闭、不补枪**（P120/P121 判法）。
     · 带外且 < +80 % ⇒ 单价 = Δ/(N−1) 直接可用，不再补枪（扰动区内，斜率的第二点是 N=0 那 22 遍）。
     · 带外但 ≥ +80 %（饱和）⇒ **必须补一发低档 N**（取高档的 1/8）求平台斜率，
       否则"值多少"退化成"很贵"这一句没用的话。补枪与否由这条阈值决定，不由读数好看与否决定。
   - Σ Δ ≥ +6 % ⇒ prologue/epilogue **有价** ⇒ 这才第一次给"每单元一次的 I/O"钉上真单价，
     并立刻折算"合并单元 / 让 prologue 跨单元复用能省多少"（那才是下一发）。
   - Δ 落进 Σ ±2 % 噪声带 ⇒ **按已定口径关闭这根杠杆**（P120/P121 的判法：带内 = 一发关闭、
     不补枪）⇒ 那 ≈70 % 里"每单元 I/O"这个落点也判空 ⇒ 剩下的候选只剩"每单元没填满就得收工"
     这件事本身（chunk 数 = ⌈6.6/48⌉ 的浪费 ⇒ 那是 **n_blk 与 fill 的匹配**，不是任何一段代码）。
   - 🔴 若某一臂**逐点**出现正负分裂（P127 教的），单点读数必须**两遍同字节复现**才许引用。

6. 顺序
   - P128（纯 host 三行的单元数护栏）已发完：Σ **+1.5 %** = 零响应，`nb` 选档轴四发结案
     （钉低档 +38~41 % / 不护栏抬档 +2.7 % / 护栏抬档 +1.5 %，`LOG#15.106`）⇒ P125 排在它后面，
     现在就是下一发。提交不限 ⇒ 两臂各一发的成本 = 两次 build + 两次发次，不构成排队理由。
   - ⚠️ 429 退避 ≥8~10 min（`#15.105` 订正）。
