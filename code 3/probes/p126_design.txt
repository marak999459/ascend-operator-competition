P126 —— 平台 `nb` 强制档 = 新模型下唯一还没被碰过的**乘数轴**（纯 host 一行，kernel 字节不动）
================================================================================

【为什么这一发值得花（P124 之后模型只剩一个未知乘数）】
  P124 把"链/死写"一起清掉之后，剩下的读数是：**每 chunk 平均只填 ≈6.6 个 token**（带 [5.2,8.0]），
  而 kernel 填满才 flush ⇒ 平台形态 = **每单元一个没填满的 chunk**。于是每单元的固定项
  （`LoadQ` + `Duplicate(o)` + `WriteOut` + 每 token 两条 gather 调用）**摊不到几个 token 上**，
  而单元数 = `rows × ⌈qN/nb⌉` —— 这是那 ≈70 % 唯一还没被量过的**乘数**。
  ⚠️ §5 #18 那条"`nb` 轴读完"是在**本地 rows≥41 靶族**上读的、结论是"auto 没选错"，
  当时**没有** V≈6.6 这个形态认识，且**平台侧从未强制扫过** ⇒ 那条不构成对本发的否决。

【本发的构造】
  只改一行：`op_host/…:36  constexpr uint32_t NB_CAND[] = {32,16,8,4,2,1};` → `{1}`。
  为什么钉**低**不钉高：`nb > nbCap(= max(NB_MIN, qN))` 的候选会被 `continue` 掉，钉高档在 qN 小的时候
  会整表被滤空 ⇒ `bestCost==0` ⇒ `CalcBlocking` 返回 false ⇒ 掉进降级块（`nb=1; n_blk=16; ks=1`），
  那是一条**巨慢且归因不清**的路。**`{1}` 永远过得了 `nbCap`，也永远装得下 UB ⇒ 零降级歧义。**
  ⛔ kernel / tiling.h / tiling_key 三枚字节一根手指都不碰（远端 **sha256 前 16 位**必须仍是
     `f815bf1eaba0f8bc` / `f2b28a86e998c194` / `1046b349538f3007`。⚠️ 设计稿第一版在这里写的
     `02dd48f9` 是 tiling_key 的 **md5**，与另外两枚的 sha256 混了口径 —— 两值同指一枚文件，无实害，
     但发次门一律按 sha256 走）。

【三条写死之前要先说清的结构性事实（读代码得出，不是猜）】
  ① **若平台某点 `qN ≤ 1`，这一发对该点是可证明的空操作**：`nbCap = max(1, qN) = 1` ⇒ 原表里
     `2,4,8,16,32` 五档本来就全被 `continue` 掉，选档结果与 `{1}` 逐位同 ⇒ **Δ 恒等于 0，不是"≈0"**。
     这一条把"读数落在 ≤ +4 %"从"没测出来"升级成"**六点全是 `qN=1`**"的强断言。
  ② `n_blk` 那个混淆**是空的**：`SFA_STAGE_MAX = 48`（tiling.h:30）把 `NBLK_CAND` 的 128/64 两档钳掉，
     而 `nb=1` 是 UB 最松的一档 ⇒ `CalcUbNeed(1,48) ≤ CalcUbNeed(nb_auto,48)` 恒成立 ⇒ **钉 nb=1 之后
     `n_blk` 仍是 48**（P109 的 pick 行实证：`nb=1` 与 `auto` 都写着 `nblk=48`）。
  ③ **真混淆是 `ks`**：单元数 ∝ ⌈qN/nb⌉，而门 ① 是 `units0·ks ≤ 40` ⇒ 钉低会把 kv_shard 深度**砍掉**。
     所以本发读的是"nb=1 时整个模型重算出来的那套档"，不是"只有 nb 变了"。⛔ 不许把 Δ126 全记到 `nb` 头上。

【预登记判据（读数前写下，读后不改；口径 = 对同字节池均值 66.05 的 Σ 相对差，带 ±2 %）】
  · **Δ126 ≤ +4 %（含负）⇒ 六点全在 `qN=1`**（由上面 ①：这不是"没测出来"而是可证明空操作）
    ⇒ ① **没有 `nb` 杠杆**（反向钉高档无从钉起，`nbCap` 就是那道墙）；② 70 % 只能挂在
    `rows × 每行常数` 上 ⇒ **P125 从"排队定价"升格为唯一手段**，且"每单元"与"每头"两个口径合一。
  · **Δ126 ≥ +25 % ⇒ `qN > 1`（至少一部分点）且 auto 远没吃满** ⇒ 🔴 反向臂第一次有靶：
    把 `nb` 钉到 auto 之上（`{nb_auto 上一档}`，受 UB 与 `nbCap` 钳）是**正收益**方向，
    值 ≥ 1.7 分（= P114 那 18 % 的一半），下一发直接发正收益臂；这一发的"变慢"就是它的定价凭据。
  · **+4 % < Δ126 < +25 %** ⇒ 六点里**只有部分点 `qN>1`**（这本身就是六点形态的新信息，能落到逐点读数上）
    ⇒ 只读逐点形状 + 记一条"每单元单价"进 §4，不补第二枪。
  三条岔路**都要改文档里的现话**（要么 §5 #18 那条"`nb` 轴读完"要加限定、要么 70 % 的落点要换乘数），
  所以这一发没有"读了等于没读"的分支。

【硬前置（三件）与它们**在本发次里各自怎么过**】
  ① **数值门**：`超差 0` 是硬门（13 真 expect × 双 dtype + 13 golden）。
     ⚠️ 订正设计稿第一版：逐位一致**只在 pick 未变的用例上是断言**；`qN>1` 的用例上 pin 会连带把 `ks`
     从 2 砍到 1（见结构事实 ③），那是**合法的重算**（合并树变了），逐位必然变 ⇒ 那种用例掉出
     "逐位一致"不是补丁错。判定口径改成两句：**超差必须 0；掉逐位的用例必须能归因到 `ks` 变了。**
     ⛔ 全程不许 `act=write` 进 `golden/`。
  ② **不是空操作**：✅ **已由 `probes/p109_nbgrid.txt` 结掉**（不必重跑）。那一发用 `SFA_FORCE_NB=1`
     —— 它把候选 `!=1` 的档全 `continue` 掉，**与把表钉成 `{1}` 送进 `CalcBlocking` 的是同一个参数**，
     而 `n_blk`/`ks` 仍由模型自算 ⇒ 选出的 tiling 与本发逐字段等价（不是靠"不覆盖"这种措辞推断的）。
     实测 `nb=1` 对 `auto`：`w3` 5.4435→5.9739 = **+9.7 %**、`w4` 9.5277→11.9275 = **+25.2 %**、
     `big1` 0.6700→0.9576 = **+42.9 %**、`w2` 1.3804→1.8546 = **+34.4 %**、
     `p32s1c16384` 5.9106→9.0670 = **+53.4 %**，且两臂 pick 都是 `nblk=48`（结构事实 ② 的实证）。
     ⇒ 本地 Δ 显著非零，这一发在本地不是空操作；平台读数是"这些点在平台上是哪一族"的那个未知量。
  ③ **命中数门（§7 第 2 条）**：远端 `grep -c 'NB_CAND\[\] = {1}'` = 1、`grep -c 'NB_CAND'` = **4**
     （行 36/229/241/244 —— 设计稿第一版写 3 是数错了，`grep -c` 数的是**行**）、
     `grep -c '{32, 16, 8, 4, 2, 1}'` = 0，且 kernel 三枚 sha 与 pristine 逐个吻合。
