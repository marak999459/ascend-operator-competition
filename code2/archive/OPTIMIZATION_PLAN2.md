## 2. 不可绕过的正确性边界

1. 现有通过版本冻结为 B0。每个候选从 B0 或已晋升版本派生，保存源码、构建参数、哈希和结果；出错回退候选，不覆盖 B0。
2. 先核对官网模板与真实调用接口。题面 x/output/numIters、可选 normOut/sumOut 与现有 logits/weights/iterations/mask 有差异；题面 softmax+eps 与代码分母+eps 也不同。为已通过接口建立兼容参考，同时建立题面参考，差异单独记录。若新模板改变必需接口，先解决契约再优化，不混在一个实验中。
3. 不减少 numIters，不按结果接近 1/n 就提前结束，不以常数输出或隐藏用例猜测取巧。行列和只是辅助指标，不能代替逐元素对拍；有限次迭代加 eps 时也不强求数学上的精确双随机。
4. 核间任务互不重叠，不引入 SyncAll；保留 UB→GM 批量写回，不恢复 GM 逐元素 SetValue。
5. 不凭“看起来多余”删除同步。先画出 MTE2→Vector、Vector→Scalar、Scalar→Vector、Vector→MTE3、输出缓冲复用的依赖，按本机 CANN 9.0.0 / 910B 支持的事件、队列规则实现。单流水屏障不能不加验证地代替跨流水同步。
6. padding 必须有语义：求和的无效元素为0，softmax 最大值/指数阶段使用合适屏蔽策略；不能把 exp(0)=1 的填充项算入归约。尾块无效矩阵不读写 GM。
7. 发布源码不含调试输出和临时探针。性能诊断产物在独立目录；提交仅传官网要求的源码字段。

## 3. 阶段 P0：连接、冻结、工具准备

输入：用户确认 NPU 已连接，以及现场有效连接配置。CPU/NPU 路径和挂载是否共享必须实查。

操作：

1. 一次 SSH 验证；失败即报告，不循环探测。读取芯片、驱动、CANN、编译器、可用 AIV 核数、设备是否有其他任务。不得写死40核。
2. source 实际 NPU set_env.sh；确认运行时没有意外链接 CPU 模拟器库。记录 CANN 路径、设备信息、编译器版本、时钟/功耗状态（权限允许时只读检查）。
3. 在独立工作目录保存 B0，核对与本次已通过源码的 SHA-256。建立 `baseline/`、`variants/`、`build/<variant>/`、`results/<run-id>/`；不能复用他人的固定 `~/mhc_build` 目录。
4. 检查 `msprof op --help` 和 ACL 计时 API 在当前版本的支持情况。未安装 profiler 时先用可靠设备事件计时，不阻塞全部工作。
5. 改造构建入口，接收 project/build/vendor 参数，设置 `set -euo pipefail`，完整保存编译日志。旧 run.sh 写死路径、默认旧内核、通过管道截断错误，不可直接作为新基准入口。

产物：`environment.json`、`baseline_manifest.json`、可独立构建和加载 B0 的脚本。验收：产物时间戳与哈希更新，加载路径确认属于 B0，烟雾运行成功。

## 4. 阶段 P1：先建立可信的正确性和计时脚手架

当前 refs harness 固定 FP16，不能用其通过结论替代 FP32 验证。先复制到本题独立测试目录修改，不影响历史脚手架。

正确性：

- 根据实际生成的 aclnn 头文件绑定参数顺序，输入输出使用 ACL_FLOAT 和4字节数据；dtype转换、文件读取写入、比较、字节数检查同步调整。
- 两套参考：按题面建立高精度数学参考；按当前接口建立 FP32 兼容参考。不能通过把容差放宽来掩盖两者差异。
- 从官方公开校验说明获得 atol/rtol；缺失则报告误差分布及与 B0 的差异，平台 Pass 是平台维度的必要门槛，不自行宣称满足所有规格。
- `NaN/Inf`、有限值掩码、最大绝对误差、最大相对误差分别比较；非有限值按官方规则判定。
- 固定随机 seed=0/1/2，保存输入和参考哈希；改变输入或 eps/iters 必须重算参考。

回归分层：

| 层级 | 配置 | 使用时机 |
|---|---|---|
| 烟雾 | n=4/6/8，batch=1/20，iters=1/20，eps=1e-6 | 每个候选首次构建 |
| 标准 | n=4/6/8；batch=1/2/7/20/39/40/41/64/100/1024/8192；iters=1/2/20/100；3个seed | 准备晋升候选；按设备核心数补充 C-1/C/C+1 |
| 尾块 | 每个打包粒度 K 的 K-1/K/K+1、C*K±1（正数） | 调整tiling、布局、打包时 |
| 语义 | 3D/4D；常量、非均匀随机、尖峰、合法范围极值；合法eps边界；特殊浮点；可选输出若接口支持 | 所有晋升候选，数值改动时重点 |

测量：

1. 将内存分配、数据上传、初始化、workspace获取、首次编译/加载移出 kernel 计时；另报完整调用端到端时间。
2. 预热至少20次；对极短算子以同一 stream 的设备事件包围一组调用，组末同步，除以次数。依据精度校准每组次数（建议100–1000），保存5组以上中位数、P90及离散程度。
3. 候选与 B0 交替测量（A/B/A/B），同一数据、设备、编译选项、时钟条件；不并发跑多个候选。计时集合排除 profiler 扰动，另做 profiling 采样。
4. 单独记录缓存热/冷策略；不要用人为刷缓存所得成绩冒充平台口径。记录每次调用是否恢复输入，禁止在输出上迭代测试而悄悄改变工作负载。
5. 主指标是 NPU kernel 延迟，辅以端到端耗时。平台 time 在确认单位和含义前始终保留原字段名。

产物：FP32 reference/harness、固定用例清单、B0 latency.csv、完整校验报告。验收：B0 可复现，误差与计时口径清楚；否则暂停内核优化，先修工具。

## 5. 阶段 P2–P7：按收益与风险逐项实验

每个实验只改变一个主要因素。每轮先烟雾/定向回归，再计时；准备晋升时跑标准及语义回归。无收益就保留报告并放弃，不为了“优化过”保留复杂代码。

| 阶段 | 实验与实施内容 | 观察指标与进入条件 | 回退条件 |
|---|---|---|---|
| P2 定位 | n=4/6/8，batch小/大，iters=1/20/100分别采集 MTE、Vector、Scalar、同步等待；确认热区和指令比例 | 输出瓶颈排序；不同shape可不同 | 采集使运行异常则先恢复正常构建 |
| P3-A 核数调度 | 将 blockDim 从固定全部核改为候选 C=min(batch,可用AIV核数)，并测试更少核；按C重新分配 batchPerCore | 小batch空核开销及大batch吞吐；记录空核数 | 尾块丢失、任务重叠、任一关键场景明显退化 |
| P3-B 搬运合并 | 保持计算布局与算术不变，尝试用多block DataCopyPad合并逐行搬运；n=8尝试整矩阵搬运；n=4/6严格核对GM/UB步长单位 | DMA指令数量、MTE耗时、n=6边界 | 跨行填充混入有效元素、越界、收益不显著 |
| P3-C n特化 | n=4/6/8编译期模板特化，保留numIters语义，试有限循环展开；避免展开全部100轮 | 标量控制指令、代码体积、编译时间 | 指令体积增大导致回退，或者影响模板绑定 |
| P4 向量内归约广播 | 减少逐行 ReduceSum→GetValue→标量倒数→Muls；尝试多行归约和向量广播/Div，让结果留在UB；先保持运算次序可比 | 标量访问、同步等待、FP32误差 | 归约跨矩阵串扰、精度超界；保留原路径 |
| P5 多矩阵打包 | K=2/4/8/16逐步测试，比较[matrix,row,col_pad]与[row,col,matrix_lane]；建立独立layout变体，不一次同时改算法 | 向量有效lane比例、重排代价、UB占用、有效核数 | 重排成本超过收益，小batch并行度被打包压低 |
| P6 同步精简 | 在P4/P5稳定后按依赖图，以合法队列/事件替代过宽屏障；每次只改一组依赖 | 等待周期、重复运行稳定性；检查编译器自动同步 | 偶发错、读旧UB、写回完成前复用buffer，立即恢复 |
| P7 流水与尾块 | 仅在多tile大batch且MTE成为瓶颈时试双缓冲；UB容量包含全部临时空间及队列buffer | Copy/Compute重叠、总耗时 | 小shape变慢、UB不足；小batch保留单缓冲 |

P3各实验可由 profiling 结果调整先后，但仍逐一测量。不要为了“满核”拆分单个4×4、6×6、8×8矩阵跨核计算；其通信和同步成本可能超过收益。K与核数要一起做小规模网格搜索，而不是无条件K越大越好。

## 6. 慎重的数值和算法重构（P8，可选，最后考虑）

仅当实现级优化收益趋于稳定、已建立可靠误差证据后执行。

- Div替换为倒数+Mul、倒数近似或迭代修正：必须计入倒数、广播和修正成本；长迭代会累计误差，覆盖iters=100和eps边界。
- softmax 减最大值提高稳定性：不是默认等价的纯性能修改。当前分母加eps的实现对缩放可能敏感；必须先澄清题面与平台接口，作为单独正确性修复/数值实验，不混入性能变体。
- 调整归约树或行列计算顺序会改变舍入；不得交换依赖的行列归一化阶段。不能把浮点数学等价视作平台数值等价。
- 不默认使用FP16中间值、不减少迭代、不移除可选输出的合法行为。Cube/MatMul框架对本题小矩阵归一化不作为首选方向。

产物：数学推导、误差报告、A/B性能证据。未过误差/规格门槛则不提交，继续使用P3–P7最佳版本。

## 8. 晋升、平台提交与停止规则

- 提议工程筛选阈值：关键场景延迟改善至少5%，且超过重复测量波动；通常不得有关键case回退超过3%。这是可调整的实验规则，不是官方评分标准。小于阈值但复杂度明显降低的修改可另行评估。
- 按实际官方评分权重汇总；权重未知时报告逐case提升和本地几何平均，不称其为平台得分。依shape使用不同路径时，分支只依据合法输入元数据，不依赖猜测的隐藏case。
- 保存 baseline、best-local、best-platform 三个状态；最新候选不自动成为最终交付。题目目前按latest排名，提交一个更慢版本可能影响排名，平台验证只用于经过筛选的候选。
- 实施回合只有获得用户对该阶段优化/提交的授权后才启动；已有会话中的明确授权不重复询问。本轮制定方案不等于现在开始改码或连续提交。
- 候选准备好后：调试输出扫描 → 打包字段与哈希核对 → `cannjudge.sh submit --problem-id 6a7c2267a52e0f540a8a02bd --project-dir <候选源码目录> --dry-run` → 一次正式提交 → 记录 submissionId → 查询至终态。
- 提交失败或响应缺ID不自动重复POST；先查记录判定是否已受理。SSH失败不重试，平台错误如实报告。Running不能算完成。
- 平台全部Pass且性能收益成立才晋升best-platform；Compile Error/WA/超时保留完整证据，回退本地候选并定位，不盲目连续提交。
- 同一方向两轮没有超过噪声的收益则转向；仅启动开销占主导时不继续堆叠复杂结构。长期目标按实测下限调整，不预承诺1.5µs。

每轮保存以下字段：variant、parent、源码哈希、编译产物哈希、CANN/芯片、n/batch/iters/eps/dtype、K/C、seed、校验误差、计时方法及单位、median/P90/波动、相对B0和当前best提升、profiling解释、提交ID/平台结果、保留或放弃原因。同步更新 `../../code2.md`，失败路径也要记录。

## 9. 下次开始执行时的第一批任务

1. 确认NPU连接，读取本方案和code2最新记录，冻结B0。
2. 建立隔离构建和FP32正确性/计时脚手架，先复现B0。
3. 对小batch与大batch各选n=6/8、iters=20做profiling；必要时加入n=4。
4. 优先尝试P3-A核数调度；若profiling显示DMA/同步占比极低，则按证据转向P4。
5. 第一轮只交付可信基线、一个候选的对照结果和下一步结论，不同时重写tiling、布局、归约、同步。

NPU未就绪时可以在CPU完成参考、用例、日志规范和源码检查；不能用CPU时间证明NPU加速。
