## 2. ⭐ 小档瓶颈诊断：**scalar-bound**（这是本文件最有价值的一条）

### 2.1 实测（来源：`code1/npu_debug/prof/blockdim_20260920/` 的 51 份 `op_summary.csv`，用加固版摘要器读）

形状 c0 = `S=64 D=256 m=2 fp16`（IO 96KB），剔首 mean：

| blk | Total | `aiv` | `mte2` | `mte3` | **`scalar`** | 每核单元数 |
|---|---|---|---|---|---|---|
| 1 | 12.6 | 12.1 | 6.9 | 8.3 | **8.9** | 64 |
| 2 | 7.0 | 6.4 | 3.5 | 4.1 | **4.8** | 32 |
| 4 | 4.3 | 3.7 | 1.9 | 2.1 | **2.8** | 16 |
| 8 | 3.2 | 2.3 | 1.0 | 1.0 | **1.8** | 8 |
| **12（现行）** | **3.0** | 2.0 | 0.7 | 0.7 | **1.6** | ~5.3 |
| 16 | 2.9~3.2 | 1.9~2.0 | 0.6~0.7 | 0.5 | **1.4~1.6** | 4 |
| 24 | 3.4~3.7 | 2.0~2.2 | 0.7~0.8 | 0.3 | **1.5~1.6** | ~2.7 |
| 40 | 4.1~4.5 | 2.4~2.6 | 1.0~1.2 | 0.2 | **1.4~1.6** | ~1.6 |

### 2.2 三条读法与推论

1. ✅ **`scalar` 恒在 1.4~1.6µs**，占 `aiv`(2.0) 的 3/4、占总时长(3.0) 的一半 —— 而 `mte2`/`mte3` 各仅 0.7µs。
   ⇒ 🟡 **小档是 scalar-bound，不是 barrier-bound、也不是带宽/DMA-bound。**
2. ✅ 这**解释了 `code1.md §19.1` 那个反直觉的数**：`nob`（4 道 barrier 全删）只省 0.45µs —— 因为删 barrier 不动 scalar。
   ⇒ 🟡 **§19 把 barrier 定为靶子，方向偏了一格**（这是我对你们结论的唯一实质异议，且**你们的实测数据本身就支持**）。
3. ✅ `scalar` 随"每核单元数"下降而下降（64→8.9、5.3→1.6），**但在 ~1.4µs 处见底**，与核数无关。

### 2.3 ⚠️ 但把 scalar 治到零，也到不了榜首（**这一步很重要，别高估 scalar 路线**）

```
aiv = max(scalar, mte2, mte3)      （流水线重叠）
scalar: 1.6 → 0 时，总时长最多降 (2.0 − 0.7) = 1.3µs
⇒ 我方内核下限 ≈ 3.0 − 1.3 = 1.7µs ；加平台侧 ~0.7µs ⇒ 平台最好 ≈ 2.4µs
```
**而榜首 1.46~1.54µs** ⇒ 🟡 **还缺 ~0.9~1.0µs 未归属**，它必须是下面三者之一，而它们**互斥且可判**：

| 候选 | 含义 | 判据 |
|---|---|---|
| **(a) tiling 执行时间** | 平台 `time` 若含 `TilingFunc` 执行，我方实测内核 2.9~3.0 vs 平台 3.68 ⇒ 差 **0.7µs** 正落在这一项 | 🔵 `tiling_cost` 探针 |
| **(b) 每核固定成本** | 我方 `empty` 地板 1.9~2.0µs，**榜首 1.54 < 我方地板** | (a) 若不成立，只剩这条 |
| **(c) 形状不同** | case1 未必是我猜的 `S=64/D=256/m=2` | 🔵 用 tiling 打印反推平台形状 |

🔑 **一个探针就能定分叉**：(a) 成立 ⇒ 那 0.7µs 在 host 侧、内核仍有 ~1µs 空间；
(a) 不成立 ⇒ 平台 `time` 即内核时长，**则榜首比我方"空 kernel"还快 ⇒ 靶子在序言/派发**。

## 5. ⚠️ 我提出的、尚未验证的线索（**别当结论**）

### 5.1 `code1.md §14.9` 的"源冻结不存在"可能源于**探针口径填错**

- 官方 `mhc_post_arch22.h:247` 与 `mhc_post_kernel.cpp:174` **两处**都用
  `srcStride = (d − dNum) * sizeof(T)` —— 即 **`srcStride` = "块与块之间的源侧间隔(字节)"**，不是"字节步距"。
- 我方 §14.9 探针填的是 `0` / `rb(512)` / `rb/32(16)` —— **没有一个是官方那个"块间间隔"语义**。
- 按官方口径重读我方 m=2 的结果（`dstStride=0` ⇒ 目的连续、每行前 256 元素全对；`srcStride` 填非 `d−dNum` ⇒ 第二块读到源块之后的相邻字节）——**现象能对上**。
- 而官方 `USE_PERMANENT_X` 路径**就是**"一次多块 DMA 把 n 行读进 UB 常驻，逐帧读、内层只写不读"，**同架构 arch22**。
- ⚠️ **我无法在本地核实 `DataCopyExtParams` 的字段定义**（本机没有 CANN 头文件，三处 `Ascend` 路径都不存在）⇒ 整条是 🟡 推断 + ⚠️ 未验证。
- **建议**：把 §14.9 从"原理上不成立"**降级为"探针口径可疑，待用官方形状重测"**（源常驻 UB + 多块读带 gap）。若成立，前向"每核 18 次请求"可压到 2~3 次。

### 5.2 case1 / case5 是同一形状的正反向（🟡）

40 队里 case5 ≈ case1 + 0.2µs 近乎普遍（唯一例外 #23：2.22 / 4.74，疑似反向写坏）。
按我方语义前反向流量都是 `(1+m)·S·D`、本就相等 ⇒ 该规律自洽；**对称到 0.2µs 以内，暗示 m 较小（≈2）**。

### 5.3 case2 与 case4 的比值不是常数（🟡）

前 4 名 case4/case2 = 3.08~3.20，我方 2.86，`#23` 5.05、`#22` 2.77 ⇒ **不能假设判分用例只出自题面那三个档**。

### 5.4 host tiling 若贵，靶子就是那两行平台查询（🟡 + 🔵 静态定位已完成）

`op_host/mhc_expand.cpp` 的 `TilingFunc` 里，**唯一可能有非平凡成本的是 line 21-24**：

```cpp
auto platform = platform_ascendc::PlatformAscendC(context->GetPlatformInfo());  // :21
int32_t num_cores_aiv = platform.GetCoreNumAiv();                              // :22
uint64_t ub_size = 0;
platform.GetCoreMemSize(platform_ascendc::CoreMemType::UB, ub_size);           // :24
if (ub_size == 0) { ub_size = 192 * 1024; }                                    // :25-27 已有兜底
```

- `num_cores_aiv` **真在用**（line 105 起参与切分决策）⇒ 不能裸删；但**可换成常量 40**（`code1.md §14.1` 已用 msprof `Block Num` 钉死本机 AIV=40），代价是放弃换芯片自适应。
- `ub_size` 决定 `ub_budget = ub_size/4` ⇒ tile 决策依据；但**已有 `ub_size==0` 的 192KB 兜底路径**，说明"不查也能退化成可用值"。
- 其余（`GetInputShape` / `GetAttrs` / 整数 min-max）**都是轻量操作，大头不在这**。

⇒ 🟡 **候选改法很干净**：`num_cores_aiv`/`ub_size` 改常量 ⇒ 整段 `platform_ascendc::` 依赖可去掉。
**但它是否值钱，完全取决于 `tiling_cost` 探针的读数** —— 在读数出来之前不要动（属于"猜"）。

**同轮务必带上 `shape_dump`**：它的成本≈0（只是多一次构建），但能一次消掉 §2.3 的 (c)，并把 `§19.7.1` 那个"harness 镜像与 host 漂移"的坑变成机器判据。

**若要我动 `code1/` 的提交源**，优先级：
1. **scalar 瘦身**（`NextUnit` 四路 `splitMode` 编译期特化；`FwdIn`/`FwdOut` 把 `DataCopyExtParams` 提出循环；地址算术 32 位）——对大档免费（scalar 仅占 29.7/1117 = 2.7%）；
2. **重测 §14.9**（官方形状）；
3. host `TilingFunc` 瘦身（取决于 `tiling_cost` 结果）。

⚠️ 三条都必须先有 `tiling_cost`/`nopipe` 的读数，否则是猜。
